# ADR 0001: Supabase как бэкенд

## Статус

Принято, 2026-10-03.

**Часть про вход отменена
[ADR 0006](0006-open-registration-with-email-confirmation.md)** 2026-10-04:
регистрация теперь открыта, подтверждение почты включено, письма идут через
свой SMTP. Всё остальное — выбор Supabase, права, RLS, настройки проекта —
в силе.

## Контекст

Доска с самого начала многопользовательская: данные лежат под владельцем и
закрыты друг от друга. Это **задел, а не продукт** — вход настоящий,
самостоятельная регистрация закрыта, аккаунты заводятся руками, открыть
регистрацию можно потом одним переключателем. Разница в цене между заделом и
продуктом огромная, а в коде почти никакой.

Из многопользовательности следует всё остальное: файл в репозитории отпадает
сразу, потому что он не может хранить чужие данные.

Автор проекта — не бэкендер и прямо сказал, что инструменты ему «одинаково
понятны и непонятны». Довод «ты уже знаешь Supabase» поэтому почти ничего не
весил и в решении не участвовал.

Проверенные ограничения бесплатных планов на дату решения:

| | Supabase | Convex | Firebase |
|---|---|---|---|
| Засыпает без активности | **да, через 7 дней** | нет | нет |
| Файлы | 1 ГБ | 1 ГБ | **требует привязки карты** |
| База | 500 МБ | 0,5 ГБ | 1 ГБ |
| Трафик в месяц | 5 ГБ | 1 ГБ | 10 ГБ |

**Отвергнутые варианты и причины, по которым от них отказались:**

- **Convex** — был рекомендован и отклонён владельцем. Его преимущество
  настоящее: изоляция данных между пользователями пишется обычным кодом на
  TypeScript, а не политиками RLS, и для не-бэкендера это та разница, где
  ошибка означает утечку чужих данных. Проиграл желанию держать одну модель в
  голове на оба проекта автора. Второй довод против — привязка: язык запросов
  не SQL, поэтому уход означает переписывание слоя данных.
- **Firebase** — с 3 февраля 2026 файловое хранилище требует привязанной
  карты даже при нулевом расходе.
- **JSON в репозитории + плагин Vite** — предлагалось дважды до того, как
  выяснилась многопользовательность. Не может хранить чужие данные.
- **Отдельная схема в существующем проекте study-tracker** — смешивает
  пользователей журнала учёбы с пользователями доски: один инцидент с правами
  достанет оба проекта сразу.

## Решение

Supabase, отдельный проект в отдельной бесплатной организации.

Настройки проекта при создании: **«Automatically expose new tables»
выключено**, **«Enable automatic RLS» включено**. Обе ошибаются в безопасную
сторону: новая таблица не видна снаружи и без политик не читается вообще.
Значения по умолчанию дают обратное — новая таблица сразу открыта через
публичный API без защиты по строкам, а анонимный ключ лежит в клиентской
сборке в открытом виде.

Вход: почта и пароль, подтверждение почты выключено, самостоятельная
регистрация закрыта. *(Отменено ADR 0006 — см. Статус.)*

## Последствия

**RLS становится самым опасным местом проекта.** Это прямое следствие отказа
от Convex, и оно записано здесь, чтобы не удивляться потом: ошибка в политике
означает, что один пользователь видит чужое. Каждая новая таблица получает
политики осознанно, и ни одна не выкладывается наружу без них.

**Проект засыпает через семь дней без обращений.** Пока пользуешься ты один,
это мелочь. Это перестаёт быть мелочью в тот день, когда ссылку откроет кто-то
ещё и увидит сломанное приложение.

**Писем почти нет, и это сделано нарочно.** Встроенная почта Supabase шлёт
2 письма в час, поэтому magic link невозможен, подтверждение почты выключено, а
регистрация закрыта. Платой за это стало: опечатка в адресе при заведении
аккаунта делает сброс пароля недоступным.

**Вторая бесплатная организация понадобилась** — двух активных проектов на
организацию уже не хватало, оба заняты под study-tracker.

Ограничения, за которыми стоит следить: база 500 МБ, файлы 1 ГБ, трафик 5 ГБ в
месяц. При обложке около 60 КБ и срезе в 50 постов это запас на годы.
